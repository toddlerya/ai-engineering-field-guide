# 从机器学习工程师 (ML Engineer) 转型为 AI 工程师

这大概是所有转型路径中最简单的一条。两者的角色定位高度相似。你只需要在代码中，把调用本地部署模型的接口，替换为调用 OpenAI/Anthropic 的 API。剩下的工程架构几乎完全一样。


## 你已具备的优势技能

- 生产级 ML 系统运维 —— 模型部署、在线推理服务托管、系统可观测性监控。
- 熟练使用 Python，精通 PyTorch / TensorFlow。
- Docker、Kubernetes 容器化及自动化 CI/CD。
- 传统的模型评估方法与数据指标。
- 主流云平台的使用（AWS、Azure、GCP）。
- MLOps 工程实践 —— MLflow、实验追踪等。
- 底层算力与基础设施管理。
- 拥有实际微调（Fine-tuning）模型的经验。


## 你需要补充学习的知识

- **大模型 API**：OpenAI、Anthropic 等服务商的 API 调用（你可能更习惯于自己托管和加载模型权重）。
- 提示词工程 (Prompt Engineering) 与提示词版本管理。
- **RAG 架构模式**：向量数据库的应用、多级数据检索策略、合理的切片 (chunking) 技巧。
- **智能体模式 (Agent patterns)**：包含工具调用的大模型、任务推理与控制循环、最大迭代步数限制等。
- **大模型专属的评测方法**：这与你原先熟悉的经典 ML 评估指标有很大差别。你需要研究幻觉率拦截检测、大模型生成质量（LLM-as-judge）、以及工具调用准确度评度。
- 流行开发框架：LangChain、LangGraph、LlamaIndex。


## 为什么这一转型非常顺畅

机器学习工程师的职责是“将机器学习技术融合进产品中”；而 AI 工程师的职责是“将生成式 AI 技术融合进产品中”。

两者的核心差别在于：AI 工程师主要通过 API 使用第三方的闭源或开源模型，而 ML 工程师通常需要直接掌控和维护模型权重。

你之前积累的关于模型服务化、监控、CI/CD 和高可用运维的所有工程经验，都可以直接无缝套用。你作为 ML 工程师在工程实现上的底子非常扎实，现在只需重点攻克专门针对 LLM 生成式场景的科学评测（Evaluation）即可。


## 推荐转型路线

1. **上手大模型 API**：尝试调用 OpenAI/Anthropic 接口，理解强类型结构化输出与 Function Calling。
2. **掌握提示词工程**：学习提示词的调试、测试与版本控制（这与你熟知的 ML 实验追踪非常相似）。
3. **构建一个 RAG 系统**：引入向量数据库与向量嵌入（你对 Embedding 的数学含义早已了然于胸），打通检索与大模型生成回复。
4. **构建一个智能体 (Agent)**：实现工具调用、控制循环和多步评测。
5. **学习大模型评测**：掌握 LLM-as-judge 以及如何设计黄金评测集来量化回答质量。


## 时间规划

**这是所有角色中转型速度最快的。** 你已经具备了极强的工程底子与生产环境落地思维。你只需将注意力集中在 LLM 特有的应用模式上，很快就能在岗位上交付高质量产出。


## 你的独特竞争壁垒

**你对模型的底层行为有极其深刻的物理理解**。当大模型表现不佳时，你能够迅速分析出根本原因 —— 到底是提示词引导有问题、召回的上下文不够精确，还是模型本身的理论极限导致的？此外，当公网 API 方案由于隐私泄露、延迟太高或费用爆炸而无法使用时，你懂得如何在本地自建推理集群托管开源大模型。这在需要私有化/本地部署大模型的特定高端岗位中，具有极高的独特竞争价值。
