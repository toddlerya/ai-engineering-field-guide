# AI 工程师工作职责分析

基于从 2026 年 2 月至 6 月期间分 6 次抓取的 4,894 份招聘需求中提取的 33,957 条具体职责。

> [!NOTE]
> **方法论说明**：我将所有的职责描述汇总到一个文件中，并使用 AI (Claude) 对它们进行了分析和归类。这与 [技能需求分析](02-skills.md) 的纯定量统计有所不同（定量统计可以查看 [分析笔记本 (analysis notebook)](../job-market/analysis.ipynb)）——本分析主要是基于向 AI 提出的问题以及它在数据中识别出的模式。占比数字（在岗位中出现的百分比）通过关键词匹配得出，因此同一条职责描述可能被归入多个类别。虽然它可能没有严格的统计分析那么精准，但我相信它依然真实地反映了市场的真实动态。

在所有 33,957 条职责中：
- **纯 AI 开发 (AI-First) 角色**：24,905 条职责 (73.4%)
- **AI 支撑 (AI-Support) 角色**：8,254 条职责 (24.3%)
- **传统 ML 及未分类角色**：798 条职责 (2.4%)


## 2月 vs 6月：市场发生了怎样的转变

对比第一次数据抓取（2026 年 2 月，895 个岗位）和最新一次（2026 年 6 月，888 个岗位）可以发现一个清晰的趋势：招聘需求正变得更加密集（每个职位的职责要求从 6.4 条上升到 7.3 条），且更偏向于“纯 AI 开发 (AI-First)”，占比从 69.4% 上升到了 75.9%。

**角色的整体趋势是：更偏向于智能体 (Agents) 和工程落地 (Operational)，而减少了探索性 (Exploratory)。** 智能体已成为多数岗位的标配，而研究型职责占比则急剧下降。

**变动最明显的领域（单位为百分比的变化）：**

| 领域 | 2 月占比 | 6 月占比 | 变化幅度 |
|------|-----|-----|--------|
| 智能体与智能体工作流 (Agents) | 41.8% | 54.8% | +13.1 |
| 安全、防线与合规 (Security) | 35.5% | 44.9% | +9.4 |
| 系统监控与日常维护 (Monitoring) | 61.6% | 70.6% | +9.0 |
| 数据处理与流水线 (Data) | 42.6% | 50.0% | +7.4 |
| 集成 API 与第三方服务 | 60.4% | 66.6% | +6.1 |
| 研究与实验探索 (Research) | 43.1% | 30.1% | -13.1 |
| 客户与外包对接工作 (Customer) | 33.5% | 26.7% | -6.8 |
| 模型微调与训练 (Fine-tuning) | 15.4% | 12.0% | -3.4 |

**这反映出：**
- **智能体成了核心**：在短短 5 个月内，智能体从一项热门职责变成了大多数岗位的硬性要求。现在有 54.8% 的 AI 工程师招聘岗位描述了智能体相关工作。
- **生产落地指标攀升**：系统监控和安全合规要求均上涨了约 9 个百分点，这证明 AI 建设正在从“做原型演示 (Prototype)”阶段，向“构建高可靠、高治理的正式系统”演进。
- **研究探索降温**：跌幅最大的是研究与实验领域（-13.1%）。以探索和概念验证为核心的岗位越来越少，以交付和线上运维为主的岗位成了主流。
- **客户对接和微调进一步减少**：这符合大趋势，即核心工作是构建和运行系统，而非定制化的客户服务或模型训练。


## 频率等级指南

我们根据某个职责在 4,894 份岗位描述中出现的频率（而非纯词频）来划分其普遍程度：

| 普及度 | 定义 |
|------------|---------|
| **极常见 (Very common)** | 超过 50% 的招聘启事中均有提及 |
| **常见 (Common)** | 在 25.0% - 50.0% 的招聘启事中提及 |
| **较少见 (Uncommon)** | 在 15.0% - 25.0% 的招聘启事中提及 |
| **罕见 (Rare)** | 仅在极少数（低于 15.0%）的招聘启事中提及 |

## AI 工程师解决的实际问题

根据他们解决的**业务问题**（而非技术分类）划分，并按照岗位覆盖率高低进行整理：


## 极常见 (Very Common)

### 1. 构建 AI 系统 (Building AI Systems)
*在 98.1% 的招聘需求中出现 (共 16,812 条职责)*

* **面临问题**：企业需要开发特定的 AI 系统来解决具体的业务问题。
* **主要工作**：
  - 实现基于 LLM 的功能，包括计算机控制、评测系统以及语音智能体。
  - 在合规的数据集框架下设计、构建并维护 AI 模型和应用程序。
  - 设计 AI 交互的用户体验（UX）模式，例如流式输出（streaming）、重试机制（retries）和局部结果展示。
  - 自动执行模型部署、回滚、扩缩容以及生命周期管理。
* **细分模式**：
  - **AI 智能体与工作流**：使用多步规划和工具调用框架构建自主 Agent。
  - **聊天机器人与对话式 AI**：设计包含上下文管理机制的对话界面。
  - **RAG 系统**：利用向量数据库实现检索增强生成。
  - **评估系统**：构建衡量 AI 质量与性能的测试框架。
  - **大模型推荐系统**：使用 LLM（而非传统 ML）进行个性化推荐。
  - **生成式视觉**：利用扩散模型等生成式 AI 进行图像/视频生成。
* **核心挑战**：将业务痛点转化为稳定、可扩展且易于维护的线上 AI 系统。

### 2. 生产落地化 (Productionizing AI)
*部署/生产环境要求在 78.3% 的岗位中出现；监控/维护在 64.3% 的岗位中出现*

* **面临问题**：在 Jupyter Notebook 中运行良好的 AI 往往在生产环境中频繁出错。系统的可靠性、扩缩容与可观测性是难点。
* **主要工作**：
  - 负责将基于大模型或 RAG 的方案从原型 MVP 推进到大规模生产环境。
  - 全栈式负责功能开发：包括前端 UI 联调、API 设计、后端服务、数据流水线等。
  - 与传统软件及产品团队紧密配合，实现可靠 AI 功能的大规模上线。
  - 推动企业内部共享平台服务的使用，如 LLM 统一网关、评估框架和监控面板。
  - 维护值班文档 (runbooks)、服务等级目标 (SLOs)、事故复盘，并在 AI 方案中嵌入可观测性。
* **细分模式**：
  - **API 设计与模型推理服务**：构建高吞吐、低延迟的 AI 计算服务。
  - **大模型部署策略选择**：在商业 API、开源模型和微调模型之间做架构权衡。
  - **监控与可观测性**：追踪大模型专有的核心指标（Token 消耗、成本、延迟、幻觉率）。
  - **扩容与基础设施**：应对流量洪峰，管理 GPU 资源，保障高可用。
  - **生产环境高可用**：参与轮班、响应故障、编写值班指南并进行事故后复盘。
* **核心挑战**：在保障低成本和良好扩容性的同时，确保具有概率不确定性的 AI 系统在生产环境中足够稳定。

### 3. 评估与质量保障 (Evaluation and Quality)
*在 68.5% 的招聘需求中出现 (共 5,959 条职责)*

* **面临问题**：AI 系统可能会产生幻觉、输出偏见或出现意外的失败。质量保障（QA）至关重要。
* **主要工作**：
  - 开发评估框架：包括离线基准测试、安全测试、回归测试集以及“大模型作为裁判 (LLM-as-judge)”的评测流水线。
  - 借助护栏 (guardrails)、实时监控和多层评估框架来确保 AI 输出的安全性和可靠性。
  - 针对网络安全等特定场景构建和评测有监督/无监督 ML 模型。
  - 校验 RAG 全链路：包括向量嵌入的精确度、检索召回的质量以及模型最终回复的准确性。
* **细分模式**：
  - **评估框架**：在上线前构建自动化测试系统来评测 AI 表现。
  - **安全护栏**：实现内容过滤、输入输出校验以及人机协同 (Human-in-the-loop) 审核流。
  - **幻觉检测**：采用带引用的 RAG 模式、忠实度评测指标及上下文精细工程。
  - **偏见与公平性**：进行偏见测试，确保不同用户群体的输出公平一致。
  - **人机协作设计**：设计带有反馈机制的高效人工审核工作流。
* **核心挑战**：为非确定性系统定义有实际意义的评测指标，并在上线前拦截所有边界失败案例。

### 4. API 与第三方服务集成 (Integrating APIs and Services)
*在 62.4% 的招聘需求中出现 (共 4,724 条职责)*

* **面临问题**：公司需要在不重构全部系统的前提下，将 LLM 能力嵌入到现有的产品和数据系统里。
* **主要工作**：
  - 将 AI 编排层与 Python、SQL 以及 Snowflake 数据流水线打通。
  - 将 AI 能力安全地集成到符合 HIPAA 等合规要求的 SaaS 平台及医疗系统 (EHR) 中。
  - 全栈配合，将前端交互与 Python/FastAPI 后端服务连接。
  - 编写 MCP (Model Context Protocol) 服务和各类工具的集成逻辑。
  - 使用 OpenTelemetry 或 Datadog 集成链路追踪，实现分布式系统的可观测性。
* **细分模式**：
  - **大模型 API 对接**：对接 OpenAI、Anthropic、Google 等主流大模型。
  - **API 密钥管理与限流**：处理 API 报错、重试机制、降级备份方案及成本控制。
  - **工具与函数调用 (Function Calling)**：将 LLM 与内部数据库、MCP 服务和 SDK 连接起来。
  - **遗留系统融合**：将 AI 能力接入 ERP、CRM、EHR 等企业级遗留系统。
* **核心挑战**：在控制成本、应对限流以及 API 经常变动的前提下，在第三方 API 和内部业务逻辑之上构建出稳健的应用。

### 5. 基础设施与开发平台 (Infrastructure and Platforms)
*在 69.2% 的招聘需求中出现 (共 6,076 条职责)*

* **面临问题**：AI 落地需要专门的基础设施，例如 GPU 集群、MLOps 工具链和高性能存储。
* **主要工作**：
  - 编写设计文档为 AI 平台层制定技术路线，并亲自开发核心组件。
  - 构建并优化兼顾安全与扩容性的企业级生成式 AI 平台，支持敏感的文档管理与数据脱敏。
  - 为生产环境中的 AI 系统（包括数据流水线和模型服务）制定并推行架构规范。
  - 使用脚本和基础设施即代码 (IaC) 技术，自动化日常运维和工作流。
* **细分模式**：
  - **AI 平台工程**：构建具备模型评测、实验迭代、上下文管理的内部开发平台。
  - **GPU 与算力资源管理**：管理 GPU 的算力分配、控制闲置成本并保障高可用。
  - **向量数据库运维**：落地包含向量检索、重排 (reranking) 以及源归属归纳的 RAG 系统。
  - **模型与提示词注册中心**：对 LLM 版本、微调模型、提示词模板及 RAG 参数进行版本管理。
  - **实验追踪**：追踪提示词调整过程、RAG 参数变化和最终的对比评测结果。
  - **安全与合规保障**：实现鉴权、敏感数据（PHI/PII）识别和加密存储。
* **核心挑战**：在 AI 技术瞬息万变的背景下，既要保持系统底层架构的稳定性，又要提供足够弹性的平台能力支持多样的上层业务。

### 6. 团队协作与业务沟通 (Collaboration and Communication)
*在 68.2% 的招聘需求中出现 (共 4,184 条职责)*

* **面临问题**：AI 工程师不能闭门造车，必须与产品、数据、传统工程以及业务团队紧密配合。
* **主要工作**：
  - 与工程师和产品经理合作，共同制定方案假设、验证路径和预期指标。
  - 与业务部门对接，寻找自动化提效的机会，并把业务痛点转化为技术需求。
  - 配合算法团队，把 AI 决策流与传统的信号处理或计算机视觉流水线进行集成。
  - 汇总各方利益相关者的意见，对实验数据进行可视化，并向管理层汇报成果。
* **细分模式**：
  - **跨部门合作**：与普通软开人员、科研学者、PM 以及垂直业务专家打交道。
  - **干系人管理**：明确并拆解业务指标，管理预期，合理排期。
  - **技术领导力**：代码评审（Code Review）、技术传帮带以及提高团队代码门槛。
  - **文档撰写**：为模型逻辑、系统流程和开发规范编写文档。
  - **客户售前沟通**：配合技术销售流程，提供方案架构设计并收集客户反馈。
* **核心挑战**：在应对多条线排期冲突的同时，做好技术与非技术层面的沟通桥梁。

### 7. 性能优化 (Performance Optimization)
*在 57.2% 的招聘需求中出现 (共 4,280 条职责)*

* **面临问题**：AI 系统响应慢、费用高、偶然出错率高，上线前必须做深度优化。
* **主要工作**：
  - 通过性能分析 (profiling)、提示词调优和缓存策略，优化 AI Agent 的耗时、费用和效果。
  - 在 GPU 和计算平台上设计并实施监控和性能调优。
  - 针对具体的业务场景定制并微调模型，以最大化其能效。
  - 发现底层第三方库的性能瓶颈，并通过重构系统架构来降低整体算力消耗。
* **细分模式**：
  - **降低时延**：应用缓存 (caching)、批处理 (batching)、流式响应和模型蒸馏技术。
  - **成本控制**：对 Token 消耗进行统计，基于任务复杂度进行模型路由，以及提示词压缩。
  - **提升吞吐**：实现离线批推理、合理的 GPU 任务调度以及自动扩缩容。
  - **算力能效比**：运用模型量化 (quantization)、更小尺寸模型以及高效的检索架构。
* **核心挑战**：在保障产出质量不降的前提下压低响应时延，控制高昂的计算成本，并兼容多样化的部署环境。


## 常见 (Common)

### 1. 数据处理 (Data Processing)
*在 49.0% 的岗位中出现 (共 3,667 条职责)*

* **面临问题**：AI 系统需要高质量、结构清晰的数据。数据清洗与转换是极为繁重的基础工作。
* **主要工作**：
  - 设计并运行大规模 ML/AI 的数据清洗和灌入流水线。
  - 编写专门用于文本清洗、格式转换、分块 (chunking) 以及向量嵌入生成的处理流。
  - 处理图像、视频、音频、纯文本和结构化数据等多模态数据集。
* **核心挑战**：在大规模数据灌入的同时确保清洗后的数据质量，处理种类繁多的非结构化源数据，并保障流水线的稳健。

### 2. 智能体与智能体工作流 (Agents and Agentic Workflows)
*在 48.4% 的岗位中出现 (共 4,630 条职责)*

* **面临问题**：企业需要 AI 能替人做决策并执行动作，而不仅是生成文本。这需要对 Agent 的编排、记忆体和工具调用进行深度开发。
* **主要工作**：
  - 在智能体设计模式上提供架构指导、代码评审和工程探索。
  - 深入一线了解业务流，利用 AI 智能体寻找流程自动化提效的机会。
  - 编写对抗性测试集（红队测试），系统性地发现并拦截智能体的意外偏离行为。
* **核心挑战**：设计出能够稳定进行多步逻辑规划、保持长上下文记忆一致性、在工具报错时实现自我修复并协调多个专项 Agent 的智能体系统。

### 3. RAG 与知识检索 (RAG and Retrieval)
*在 42.0% 的岗位中出现 (共 2,704 条职责)*

* **面临问题**：企业需要大模型能够安全访问其内部私有的敏感资产，传统的关键字匹配检索已无法满足要求。
* **主要工作**：
  - 设计并优化基于最新 LLM 技术的 RAG（检索增强生成）系统。
  - 部署生产级的 RAG 工作流和内部智能问答工具。
  - 设计并调优切分策略 (chunking) 和多维嵌入表示。
* **细分模式**：
  - **非结构化文档解析与切分**：兼容 PDF、Word、HTML、音视频等多种源数据。
  - **向量检索与语义检索**：配合调优的索引方式实现高精度的语义匹配。
  - **知识图谱与混合检索**：将图谱关联关系与向量相似度计算结合。
  - **查询词重写与扩展**：准确揣摩用户真实意图，化解指代不明并保留历史上下文。
  - **重排 (Re-Ranking) 优化**：平衡相关性得分，针对不同类型的检索请求定向优化排序。
* **核心挑战**：在保障低时延的前提下，对大量包含了垂直专业术语的特定领域数据实现高精度、高召回的语义检索。

### 4. 安全与合规保障 (Security and Compliance)
*在 40.1% 的岗位中出现 (共 2,777 条职责)*

* **面临问题**：AI 系统的引入带来了数据泄漏、幻觉侵权、违规输出等合规与安全漏洞。
* **主要工作**：
  - 加固 CI/CD 和发布流程，提升 AI 功能的部署安全和灰度速度。
  - 确保代码安全、模型治理，并践行“负责任的 AI (Responsible AI)”开发准则。
  - 确保系统表现符合隐私保护、数据出境和道德规范护栏。
  - 借助大模型网关 (LLM Gateway) 集中进行 AI 平台的权限和鉴权管控。
* **核心挑战**：在保障业务灵活体验的同时封堵安全漏洞，确保满足不同法域的合规性（如 GDPR、HIPAA 等），并防范 AI 特有的新型攻击方式。

### 5. 研究与实验探索 (Research and Experimentation)
*在 34.9% 的岗位中出现 (共 2,377 条职责)*

* **面临问题**：AI 技术迭代速度极快。企业需要紧跟前沿论文，不断试验新的开源架构。
* **主要工作**：
  - 跟踪前沿 AI 进展，尝试多智能体编排和更具自主性的 Agent 链路。
  - 配合研究科学家 (ML/Data Scientists)，把处于实验室状态的原型和模型工程化落地。
  - 快速做产品原型的概念验证（POC），验证技术可行性。
* **核心挑战**：在高速变化的技术浪潮中，既要鼓励实验创新，又要确保线上生产系统的稳定。

### 6. 客户对接与解决方案 (Working with Customers)
*在 26.8% 的岗位中出现 (共 2,328 条职责)*

* **面临问题**：AI 项目需要真正交付给客户使用。需要理解多变的客户诉求，保障交付结果。
* **主要工作**：
  - 作为核心开发人员交付面向具体客户的 AI 解决方案或通用业务框架。
  - 与客户团队紧密配合，做需求拆解并指导客户侧系统的部署。
  - 在真实的客户侧生产环境中实施快速原型迭代和上线交付。
* **核心挑战**：用通俗的语言向非技术人员讲清楚大模型技术边界，管理客户的过高预期，确保系统能顺利被客户使用。


## 较少见 (Uncommon)

### 1. 前端与交互界面开发 (Frontend and User Interfaces)
*在 17.1% 的岗位中出现 (共 1,112 条职责)*

* **面临问题**：AI 能力需要一个优秀的交互入口。聊天面板、数据大屏和 Web 系统是用户与 AI 沟通的窗口。
* **主要工作**：
  - 参与全栈研发，既负责后端服务逻辑又开发前端 React/Next.js 页面。
  - 将 AI 节点的流式返回（Server-Sent Events）以优雅的动态效果呈现在前端页面上。
* **核心挑战**：设计直观好用的 AI 交互界面，克服网络连接抖动并解决大文本流式返回时的前端性能瓶颈。


## 罕见 (Rare)

### 1. 模型微调 (Fine-tuning Models)
*在 13.8% 的岗位中出现 (共 769 条职责)*

* **面临问题**：通用底座模型在特定的高专业度任务中表现不佳，需要通过微调来强化模型的特定能力。
* **主要工作**：
  - 使用 LoRA、PEFT、RLHF 等机制设计和运行微调流水线。
  - 配合模型训练、评测与对比实验。
* **核心挑战**：收集和清洗高质量的微调样本集，防范灾难性遗忘问题，并能科学评估微调后的模型到底变好还是变坏。

### 2. 精细提示词工程 (Prompt Engineering)
*在 10.0% 的岗位中出现 (共 501 条职责)*

* **面临问题**：要想从大模型获得高稳定性、格式严丝合缝的输出，需要将提示词当作一项系统性的工程对待，而不仅仅是随意写一段文字。
* **主要工作**：
  - 开发提示词管理框架，对提示词模板做版本控制、单元测试和回流评测。
  - 把提示词视作“代码”一样进行严格的工程管理。
* **核心挑战**：让提示词的表现具有可预测性并降低偶发漂移，建立覆盖提示词迭代的回归测试机制。

### 3. 本地化私有化部署 (Self-Hosting Models)
*在 2.5% 的岗位中出现 (共 134 条职责)*

* **面临问题**：部分企业基于隐私保密、算力成本或极低时延的要求，不能直接使用第三方的 OpenAI/Anthropic 等公网 API。
* **主要工作**：
  - 使用 vLLM、TensorRT-LLM 等推理框架搭建和调优本地大模型推理服务。
  - 对 CUDA、Triton 推理网关、TensorRT 等显卡加速层进行调优。
* **为什么私有部署如此少见？**
  - 最顶尖的模型（如 GPT-4、Claude 3.5 Sonnet）均是閉源 API。
  - 本地维护显卡和推理服务的日常运维负担巨大。
  - 在请求规模较小时，自行购买或租用 GPU 算力远贵于直接调 API。
* **何时才必须要本地化部署？**
  - **严苛的隐私安全**：军工、政府、核心金融等严禁数据外泄。
  - **极大请求规模**：日均几百万次调用时，自建推理集群的单次 Token 成本可能低于商业 API。
  - **超低时延**：例如边缘计算、局域网设备等必须在本地完成推理。


## 核心洞察

1. **“构建系统”是 AI 工程师的首要职责**  
   系统构建相关职责出现在了 98.1% 的岗位中。AI 工程师本质上首先是一个**建设者 (Builder)**。
2. **生产环境工程落地占据了工作的极大篇幅**  
   如果将部署（78.3%）、可观测性监控（64.3%）和基础设施建设（69.2%）结合来看，把原型变正式产品才是最耗时间的部分，工作量远超普通人预料。
3. **“评估与质量把控”已不是加分项，而是必修课**  
   它在 68.5% 的岗位中出现。企业需要的是在生产环境下表现足够稳定、符合安全护栏的系统。
4. **集成 API 牢牢占据主导地位，本地自建模型极少**  
   API 对接相关职责占了 62.4%，而自建模型推理服务仅有 2.5%。市场压倒性地选择使用成熟的商业大模型 API。
5. **RAG 和智能体是绝对的主流**  
   检索与 RAG 占 42.0%，智能体占 48.4%。这证明约有一半的岗位需要设计能调取外部工具、进行多步决策的高级 AI。
6. **模型微调比大众想象的要少得多**  
   微调仅在 13.8% 的岗位中出现，提示词工程在 10.0% 中提及。大多数企业的工作主要是通过 RAG、合理引导提示词以及业务逻辑集成来让底座模型生效，而非自己训模型或调权重。
