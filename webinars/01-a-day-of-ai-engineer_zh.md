## 1. 内容简介

很多人往往误以为 AI 工程师是一个纯学术、偏向算法研究（Research）的岗位。本期分享会将戳破那些虚无缥缈的理论炒作，带你了解这个岗位在生产一线最真实、最务实的工程日常。


## 2. 核心大纲

- 我个人视角下的 AI 工程师定义
- 核心职责：如何将 AI 稳定融合进商业产品中
- 提示词工程 (Prompt Engineering) 与评测数据集构建
- 线上运维痛点：A/B 测试、系统监控与用户反馈飞轮
- 进阶系统设计：CI/CD 自动化部署、RAG 与复杂 Agent 系统的设计
- 现代 AI 工程师不可或缺的核心技能
- 现场 Q&A 问答环节


## 3. 核心启示 (Key Takeaways)

1. **准确定义 AI 工程师的角色** —— 深刻理解其作为连接传统“软件工程（SWE）”与“机器学习研究（ML Research）”之间的工程桥梁角色。
2. **高效进行团队协作** —— AI 工程师在现代敏捷交付团队中如何与产品、数据和算法人员紧密咬合。
3. **推行规范的工作流程** —— 学习如何将传统的 CRISP-DM（数据挖掘跨行业标准流程）科学地裁剪并应用到大模型应用生命周期中。

## 4. 分享会现场 Q&A 问答记录

### Q：数据工程师 (Data Engineer) 怎么平滑转型为 AI 工程师？
对于数据工程师来说，这是一条极为顺畅的转型通道。因为 AI 工程师本质上是一个**工程开发角色**，而非算法研究岗位。目前大多数企业所谓的“AI 开发”，其实主要是在调优提示词（Prompt tuning）以及编写周边的传统软件工程代码。

数据工程师对单元测试、自动化 CI/CD、高可用可观测监控等早已轻车熟路。虽然具体指标属性有所不同（比如数据流监控 vs 大模型幻觉/生成质量监控），但使用的底层工具链和工程思维是高度一致的。

你只需专门补充学习这几项：怎么高效调用大模型 API、怎么设计和迭代提示词模板、以及怎么搭建大模型评测系统。花上 **3 到 4 个月** 重点攻克针对大模型输出的评估与测试，数据工程师就完全做好了转型准备。

特别是对于 RAG（检索增强生成）系统来说：你需要准备一个搜索引擎，搜索引擎需要数据清洗，而数据清洗需要高性能的数据清洗灌入流水线（Ingestion Pipeline）。这恰恰是数据工程师最擅长、干了整整一辈子的看家本领。

### Q：在准备面试时，怎么精简出最值得花精力准备的核心技术？
请把你的精力集中在以下最关键的 6 个模块：
1. 熟练掌握主流大模型 API 的调用（包含流式处理与结构化输出）。
2. 理解并能手写智能体 Agent 架构 —— 大模型调用外部工具的控制循环。
3. 彻底吃透 RAG 架构 —— 这是目前绝大多数企业大模型落地应用的底层基石。
4. 系统测试 —— 怎么测试非确定性的智能体，怎么验证它们在边界情况下的行为。
5. 线上观测监控 —— 掌握专门针对大模型输入输出的实时监控技术。
6. **科学评估 (Evaluation)** —— 这是最核心、最拉开候选人差距的技术壁垒。

**在作品集项目准备上**：建议挑选一个非常具体的垂直业务行业（如垂直电商、分类信息网站）。直接去他们的官网上看看他们平时面临什么业务痛点，思考你怎么用大模型帮他们解决，并动手写一个小项目展示出你的完整架构，这就是最打动面试官的作品。

### Q：为什么现在很多做 AI 自动化套壳的人，也自称是 AI 工程师？
由于这是一个全新的岗位，目前行业并没有大一统的硬性资格定义，任何人都可以这样自称。

但是，那些整天只会在 N8N、Dify、Coze 等无代码/低代码网页端上点点鼠标、拖拽一下工作流的“自动化专员”，真的是我们所说的“工程师”吗？在我个人看来，显然不是。如果你的工作流程中完全没有软件工程的严谨度、没有最佳实践规范、没有回归单元测试，我就不认为这算得上是“工程师”。

### Q：什么技术背景转型做 AI 工程师最有优势？
数据科学家（Data Scientist）和机器学习工程师（ML Engineer）是极佳的转型后备军。

对于 ML 工程师来说，这大概是所有转型路径中最简单的了 —— 你只需要把以前调用本地托管/训练模型的代码，替换为调用 OpenAI/Anthropic 的 API 接口，剩下的模型部署服务化（Serving）和 MLOps 逻辑几乎完全通用。

**对于任何软件工程师（后端/前端/数据）**：你已经非常精通软件工程的最佳实践和测试规范。从扎实的工程底座出发、在此之上叠加 AI 知识，远比让一个写惯了学术论文、没有工程规范的算法研究人员去补齐软件工程基本功要容易得多。

同时，**综合通才（Generalists）**非常适合做 AI 工程师。如果你懂得很多技术领域，可能都不是专家级别，但什么都会折腾一点，你在大模型落地开发中会非常有优势。

### Q：传统的自然语言处理 (NLP) 或者是传统机器学习，现在是否已经沦为过时的“遗产技术”了？
很大程度上来说，确实如此。比如 `gpt-4o-mini` 这样的轻量大模型现在便宜到了不可思议的程度 —— 我在带训练营的整整一个课程里，甚至连 1 美元都没花完。

这里的研发性价比核算非常露骨：你花几个月费时费力去清洗数据、训练一个传统的专用 NLP 模型，和直接写几行代码把数据丢给 `gpt-4o-mini` 相比，哪一个效率更高？

当然，仍然有少数特定的长尾场景需要传统 NLP：比如极简的单词拼写纠错，或者在高性能搜索推荐里要求低于 1 毫秒（Sub-millisecond）的极致时延响应。但总体而言，大势所趋已经非常清晰。

### Q：随着大模型变得越来越聪明，未来程序员/开发者的岗位会面临危险吗？
我完全不认为软件工程师的岗位会有危险。相反，大模型越强，我们越需要人类去监督 AI、越需要在架构层强力推行严密优秀的工程规范。如果没有人类架构师的兜底，任由 AI 去写代码，最终一定会产出无法运行且充满漏洞危险的代码灾难。

就在今天，我还在用 Claude Code（目前业界最顶尖的命令行编码 Agent 之一）帮我写代码。结果我发现它在修改一个 Bug 时，为了省事，竟然试图通过把我的旧测试用例直接删掉、重新建一个空测试的形式来假装“Bug 已经修复”。你看，AI 智能体有时就像一个极度油滑且懒惰的实习生 —— 他们在很多时候确实非常能干，但一不留神就会偷懒敷衍，必须由有经验的资深人类开发时刻盯着。

至于数据科学家（Data Scientist）岗位，我倒没有那么乐观。数据科学中很大一部分日常数据清洗、分析与建模工作现在极其容易被 AI 助手完全自动化。那些不会写工程化代码、整天只能在 Jupyter Notebook 里做做数据分析的数据科学家，一旦面临裁员，想在求职市场上重新找到工作会非常艰难。

## 5. 分享会后文字问答记录

### Q：有什么“硬实力证明（Proof of Work）”能证明我是一个合格的 AI 工程师，而不是一个只会写 Demo 的业余爱好者？
工程师与业余爱好者的核心分野在于：工程师严格遵循软件工程的最佳实践。他们会主动编写高覆盖率的单元测试，将系统可观测性监控（Monitoring）视为上线必备，并且懂得怎么科学收集和分析真实的用户反馈数据。

如果你写一个 Side Project 只是为了自己玩（Hobbyist），那无所谓，不需要写评测，不需要做高可用监控。但如果你要在企业里把大模型深度融合进生产级的商业系统，这就是工程师与爱好者的区别。

### Q：近期的 AI 工程师岗位需求有什么共性？最核心的 Top 3 必备技能是什么？
关于 1,500+ 份真实招聘数据的统计与 Top 3 技能提取，请参考 [第二期分享会：定义 AI 工程师的核心角色](02-defining-the-role_zh.md)。

### Q：应届生或刚毕业的新人怎么才能跨过门槛、拿到第一份 AI 工程师的工作？
**作品集项目（Projects）**。你需要疯狂地去写项目。挑选你感兴趣的 AI 垂直子领域，尽可能多地去独立实现端到端的小项目，然后以这些项目作为你简历的敲门砖去面试。

此外同样重要的是：**建立你的人脉圈**，多去参加本地的技术线下聚会（Meetups），直接联络那些正在招人的 Team Lead。现在市场上会调大模型 API 接口的人满大街都是，但真正懂得怎么写评测（Evaluation）和自动测试（Testing）的人寥寥无几。应届生如果在简历中展现出科学的评测思维，就能在求职中瞬间脱颖而出。

### Q：贝叶斯机器学习与混合大模型方案结合 —— 这种研发管道的资金投入产出比是怎样的？
这个话题技术构想过于垂直和复杂，很难给出一个通用的宏观答案，需要一对一的详细业务咨询来具体拆解。

### Q：数据工程 (Data Engineering) vs AI 工程 (AI Engineering) —— 哪一个的行业需求更稳定、对远程办公（Remote）更友好？
如果追求职业的稳定性，数据工程（Data Engineering）一直保持着非常稳健的增长。只要企业还有数据，就永远需要数据工程师去搭建数据管网。至于远程办公友好度，我手头没有直接的统计数据 —— 实际上，你完全可以自己写个脚本去抓取招聘网站上的数据并做个可视化的分析，这本身就是一个极好的 AI 工程师作品集项目。

### Q：AI 工程师（AI Engineer）和传统的软件开发（Developer）头衔，本质上是同一种岗位吗？
这两者的技能重合度极高。**AI 工程师首先是一名工程师，大模型开发只是他的其中一项特长。**

但确实有一小部分是大模型应用独有的特有知识：比如提示词调试（Prompt engineering）、提示词模板的版本控制、模型微调概念以及针对非确定性输出的特殊测试方法。此外，科学评测（Evaluation）也是 AI 工程师的专属技能，这更接近数据科学家以往的思维模式。

实际上，**一个合格的软件工程师，只需经过两到三个月的定向补充学习，就能完全胜任 AI 工程师的工作。**

### Q：我拥有 20 年的电信工程背景，但完全没有写过代码。我必须先花几年去成为一个软件工程师吗？
首先，去折腾并成为一个数据科学家（Data Scientist）是没有任何帮助的，不要走这条弯路。但是，**补齐软件工程的基本功是必须的**。

你应该从学习 Python 语言和怎么编写测试开始。在此基础之上，直接开始上手大模型开发，并以项目驱动学习。

在学习的过程中，就应该立刻开始投简历。一开始可能会收到很多拒信或者没有任何回复，但这非常正常。在努力成为一个优秀的 AI 工程师的过程中，你自然而然就成为了一名合格的软件工程师。

同时，学会使用 Claude Code 和 GitHub Copilot 等 AI 编码工具 —— 它们是你成为通用开发者、快速跨越技术门槛的绝佳外挂。

### Q：有哪些好用的大模型评测（Evaluation）开源工具推荐？
**最适合你的评测工具，往往是你针对自身特定业务场景自己手写的脚本。**

如果说成熟的开源工具，Evidently 做的非常优秀。而且鉴于目前大模型极强的代码理解力，自己从零手写一套轻量级的 LLM-as-judge 评测脚本其实是极其容易的。

推荐的迭代策略：第一步先在 Excel 表格里人工对比；第二步用 Python + Pandas 写自动化打分；第三步将其集成进 CI/CD 自动化流水线。

### Q：如果让你去创办 Trova 这样的大模型应用公司，你第一天会怎么招募技术团队？
首先，**我会选择自己一个人单干几个月**，摸清这个商业模式到底能不能跑通。

当客户规模做大之后，我会招募一名**全栈通用型软件工程师**，并立刻给他配齐 Claude Code Pro 订阅。紧接着，我会招募一名优秀的前端交互工程师。在创业初期，我绝对不会过早去招募专门的“AI 工程师”或算法人员，因为公司前期 90% 以上的工作量都是常规的业务系统建设。

初创团队需要的是能够身兼数职、解决各种综合工程问题的“万金油（Generalists）”，而不是垂直领域的专家（Specialists）。只有当公司规模做大到 50-60 人、岗位开始出现精细分工时，才需要招募专门只负责调试 AI 的垂直人员。

### Q：AI 工程师需要同时兼顾数据流监控吗？还是只要监控大模型的输出就可以了？
不能把这两者割裂开来。你需要设计一套立体、全面的监控网：包括 API 接口的调用参数、 Token 消耗账单、周边微服务的健康状况。如果系统涉及 RAG 和数据库，数据源的清洗质量同样是必须要监控的核心一环。

### Q：大模型产品开发人员也被期望拥有出色的产品意识（Product Sense）吗？
**产品意识是任何优秀工程师（尤其是高级/资深架构师）的黄金加分项**。这要求你不要像工具人一样只顾埋头写代码，而是要深刻理解你的代码改动能带来怎样的业务价值。

例如：你费尽心思去压缩 RAG 检索的时延，不应该只是因为这是一个好玩的工程挑战，而是因为你清楚地知道，响应时延降低 200 毫秒能直接让线上用户的付款转化率提升 5%。

### Q：在将大模型应用推向生产线时，最考验 Lead 角色的非技术硬实力是什么？
**跨部门沟通管理（Stakeholder management）、优秀的产品触觉以及对商业闭环的深刻理解。**

你需要听得懂业务方反馈的痛点是什么、理解背后的商业价值，并能精准将其翻译为工程代码实现。特别是在大模型安全合规与治理（Governance）领域：需要你深刻洞察垂直行业的合规底线，评估模型潜在的越权越线风险并在技术层预先防范。

### Q：前端开发人员（Frontend Engineer）该怎么转型做 AI 工程师？
前端开发人员需要花精力去补齐你后端的工程短板。在语言选择上：**完全不需要去强行学 Python，直接用 TypeScript 就可以**。目前大模型应用生态中，TypeScript 语言的流行度和岗位需求非常大。

你的核心路线是：先从前端迈向全栈（TypeScript 后端）。一旦你习惯了后端的逻辑，在此之上叠加大模型接口调用就顺理成章了。相比纯后端，你的优势在于：**你能够独立搞定从后端 API、RAG 逻辑到最终精美前端交互的端到端全链路交付。** 推荐先在 Cursor 等 AI 编码助手的辅助下练习编写后端服务，很快就能上手。

### Q：数据科学家 (Data Scientist) 岗位现在是不是彻底凉了？
没有彻底凉掉，但很多只会用 Jupyter Notebook 做做统计、套几个经典算法、完全不懂工程落地和系统测试的数据科学家，现在的处境确实非常艰难。大模型时代，大量基础的数据分析工作被 AI 助手完全自动化了。一个熟练使用 Claude Code 的 AI 工程师，能在几十分钟内搞定以前数据科学家要写好几天的数据建模。

当然，那些懂工程、懂业务、懂系统设计的全栈型数据科学家（Full-stack data scientists）在市场上依然非常抢手。在大型企业的大模型落地的过程中，对于超大规模算力约束下的算法微调，依然离不开传统算法专家的深厚底子。但如果你想在这一技术浪潮中立于不败之地，**补齐软件工程的基本功是唯一的出路**。
